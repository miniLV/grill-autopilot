# Explicit resume reconciliation

Enter only for `/grill-autopilot resume <run-id>`. The planner uses existing Git and host tools to reconcile one saved run; this is not a background recovery service. [run-record.md](run-record.md) owns fields/paths/writes, [companions.md](companions.md#fingerprint-and-resume) owns fingerprint checks, [runtimes.md](runtimes.md) owns lifecycle observations, and [failures.md](failures.md) owns deadlines, counters, stopping and terminal results.

## Qualify, observe, then continue

1. **Locate read-only.** Treat the run ID as a literal identifier, not a path: reject separators and `.`/`..`. Locate exactly one `.scratch/<slug>/runs/<run-id>/run.md` in the repository's recorded original checkout (use Git worktree registrations when invoked from a ticket/integration worktree). Read it without creating a run, selecting a new companion or running Setup. Require the requested ID, recorded ID, canonical record/tracker/original-checkout paths, repository Git common directory and owned-file manifest to agree. Require the saved base commit and paths to be attributable to that run; an existing directory or matching slug is insufficient. Duplicate/missing records, unqualified ownership or an unavailable original checkout stop resume: preserve the existing files and show a failed known-facts brief. Save that brief only at a qualified owned destination; otherwise show it directly as failures.md permits.
2. **Record the interruption safely.** Once the original record and write destinations are qualified, the planner may append a timestamped resume/interruption observation and declare exact observation-log paths before capture. State when the interruption was discovered; its cause/time may be unknown. Preserve old events, attempts, approvals, counters and input hashes. These evidence-only appends precede execution reconciliation; status transitions, dispatch, merge, retry, environment changes and cleanup wait for the facts below. Frozen snapshots and source task bodies stay unchanged.
3. **Reconcile inputs and host.** Verify saved snapshot hashes and unchanged source task bodies, then check the *saved* companion selection/fingerprint under companions.md. Inspect current host capabilities/authorized route and query every saved agent/session/process identity through runtimes.md, including preparation, reviewer, final-stage and command attempts. Attribute each identity to this run, role and worktree; a PID alone may have been reused. Capture full available results, activity, stop and capacity facts. Host migration, an unreachable identity or uncertain ownership is unknown, not proof that execution ended. Keep unknown model facts disclosed. Preserve deadlines and reconcile planned vs actually started invocations/counters from attributable evidence; no budget or deadline is renewed by resuming.
4. **Reconcile Git read-only.** In each recorded canonical worktree, capture `git worktree list --porcelain`, its symbolic ref/HEAD, `git status --porcelain --untracked-files=all`, staged/unstaged diffs and untracked inventory. Match registrations, refs and Git common directory to the record; inspect merge/rebase/conflict state too. Compare the original checkout and base ref against run-record.md's baseline. Resolve saved base/candidate/reviewed/merge SHAs as commits with `git rev-parse --verify --end-of-options '<sha>^{commit}'`; use `git merge-base --is-ancestor <candidate-sha> <current-integration-sha>` rather than branch existence to determine inclusion. Capture current branch tips and integration HEAD. Explain a moved tip only with attributable saved operation intent and Git/host evidence, such as the recorded merge finishing before its observation was saved. A dirty owned active worktree is an observation, not permission to clean it. Missing refs/worktrees are acceptable only with recorded successful owned cleanup evidence and retained commit/check objects; unexplained movement, missing objects, conflicting state or unattributable files stops recovery.
5. **Choose once from the observed facts below.** Append the decision and evidence before the corresponding permitted operation. Only after qualification and reconciliation may the planner repair mutable Status/Comments and recorded observations, then continue the original stage in [loop.md](loop.md). Reuse recorded paths, snapshots, configuration, approval and push choice. An already terminal run with consistent evidence simply shows its brief; resume does not replay delivery or cleanup. A blocked/failed run needs an evidenced repaired prerequisite and a permitted continuation under failures.md; the command itself grants no fresh retry budget.

Done when: each pending attempt and interrupted operation has an attributable continuation/terminal decision, or recovery has stopped with preserved state and a failed brief. Ambiguous host/Git/ownership or fingerprint/input drift stops new execution and **all cleanup**. Use failures.md to block affected unfinished tickets, stop only qualified owned resources where possible, retain done evidence and report unconfirmed activity/resources. If tracker write ownership is unqualified, preserve it and show those decisions directly rather than overwriting it.

For an interrupted final stage, return to [final-review.md](final-review.md) after this reconciliation. Retain final correction counts and all saved deadlines; qualify both-axis verdicts and check evidence for the exact current tip against the original saved base SHA. Historical final PASS/checks or a terminal status alone cannot qualify changed content or replay delivery.

## Decisions at the interrupted stage

| Observed facts | Resume decision |
| --- | --- |
| `claimed`/`in-review` (or another pending stage), same attributable attempt still active | Observe that identity with bounded waits through its **saved deadline**. Preserve its slot, counter and worktree; no duplicate worker, reviewer, merge or continuation message. At expiry apply failures.md's timeout/stop exit. A status row claiming inactivity cannot override live host evidence. |
| Same identity inactive, complete attributable result available; candidate not included in integration | Consume the existing result at its recorded stage, confirm release/capacity and pass normal review/integration gates. Do not repeat implementation because the source ticket still says claimed. A replay of an intended but unobserved operation requires proving it did not happen. |
| Candidate already included, recorded matching successful integration-check evidence | Reconcile the completed merge and supplement `done` without another merge, worker or reviewer. Apply the exact evidence qualification below first; a candidate's presence alone is insufficient. |
| Candidate included, merge attributable, checks absent/unreadable/incomplete or only for a different integration SHA | Preserve the old check facts as historical/missing evidence. With no possible writer and a safely attributable clean integration state, record a bounded verification attempt and rerun the ticket's agreed Verify and applicable typecheck on the **current integration SHA**. Capture actual SHA/command/cwd/exits/logs; record done only after every applicable check passes with unchanged HEAD/content. Keep an agreed N/A reason. A red/unavailable/timed-out check follows failures.md and produces a failed recovery brief; no merge replay or recovery reset. |
| Unknown identity/activity, unexplainable branch/HEAD, mismatching review/candidate, merge ownership ambiguous, unresolved Git operation or unowned dirty state | Stop resume and preserve all refs, worktrees, dirty files and evidence. Record/show failed brief with the mismatch and required human reconciliation; no automatic redispatch, reset, clean, abort or prune. |

### Qualify already-merged check evidence

Require all of these facts before supplementing `done`:

- The candidate is an immutable recorded commit, its available reviewed SHA/verdict identifies that same candidate as PASS, and Git proves the candidate is an ancestor of current integration. Missing or contradictory candidate/review/merge identity cannot be repaired by merely rerunning tests.
- Saved merge intent plus observed Git history attributes inclusion to this run's ticket. The saved/observed merge-after SHA includes the candidate. An unexpected integration/branch tip needs an evidenced explanation before any check may run.
- Every applicable agreed ticket Verify/typecheck has a successful `integration_checks` entry and readable captured log under run-record.md, binding its exact command, canonical cwd, exit and times to the **current integration SHA**. The logs must support those results; a free-standing PASS or a branch name is insufficient. Evidence for a different SHA is historical and requires bounded re-verification. The original check captured unchanged integration HEAD and clean checked content before/after, so dirty work cannot masquerade as committed-SHA evidence.
- Host facts establish no active or unknown writer affecting integration or that candidate; current integration checked content is clean and unchanged. Record old/new mutable status and the evidence that justified repair. Cleanup remains the separate gate in loop.md, never a way to make these facts true.

After a root crash or power loss, no immediate brief or automatic continuation is guaranteed. The next explicit resume can append the observed interruption only after locating/qualifying the saved record. It then follows these gates; unavailable host evidence may make safe recovery impossible.
