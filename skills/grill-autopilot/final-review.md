# Final review gate

Read at SKILL.md step 5, after any final correction, and before delivery or resuming final-stage evidence. This is the single authority for the final-tip check/review/correction sequence. [failures.md](failures.md) owns finite attempt/infrastructure handling and result classification; [runtimes.md](runtimes.md) owns permitted routes, all-role capacity, activity and release; [run-record.md](run-record.md) owns paths and durable evidence. The planner follows this protocol using existing tools.

## Qualify checks and both review axes

1. Require attributable clean integration HEAD/ref, no pending Git operation and no active/unknown writer. Resolve the exact integration commit and the run's **saved `base_sha`**, not the current base branch. Require the saved base to be an ancestor of that tip and frozen input hashes unchanged. Save the target SHA, comparison base, check/review attempt IDs, deadlines and canonical evidence destinations before operations. Unknown state/resources take failures.md's preserved-state failed exit.
2. Qualify recorded full-suite and applicable-typecheck evidence for this **exact SHA and unchanged checked content**, or run those commands in bounded final-verification attempts. Capture command, canonical cwd, times, exit/output and HEAD/ref/status/diffs/file inventory before/after; use [integration.md's owned-artifact cleanup gate](integration.md#owned-artifact-cleanup-gate) for declared check outputs. Retain agreed `N/A` with its reason; missing/unavailable checks do not pass. Red checks still proceed to review when safe.
3. Read the selected companion `code-review` skill; assign its Standards and Spec seats to the reviewer role, read-only, on the same exact integration SHA. Packets include saved base SHA, target SHA, `git diff <saved-base-sha>...<target-sha>`, canonical frozen spec, worktree/companion/evidence paths, current check failures and known blocked requirements. Use both axes after **every** correction, sequentially when capacity requires it, reconciling inactivity/release between calls. Capture each full verdict, reviewed SHA, base SHA, findings and readable evidence; a bare PASS or mismatching/missing identity/evidence cannot qualify. Spec lists known blocked requirements as **undelivered scope**, separately from findings; other spec deviations in delivered work remain findings. Standards/Spec must reject fixes that delete or weaken required assertions merely to make tests green.
4. Recheck clean unchanged HEAD/ref/content and review/check identities after both seats finish. Only two qualified **PASS** verdicts with no remaining findings and all required passing check evidence for that same current tip qualify delivery. An agreed inapplicable typecheck keeps its `N/A` reason. An initially green review/check records **zero** correction calls; a later green round retains its actual spent count. Classify through failures.md when qualified. Otherwise use the correction gate below; unavailable/invalid review follows failures.md, never an inferred PASS.

## Bounded correction rounds

`retry.final_review` is the **total correction-round limit beyond the initial review**, default **2**. It is neither extra retries per round nor ticket `retry.escalate`; initial review and post-fix reviews do not spend this budget. Run `final_fix` counts prepared correction executions actually started, once per logical round. Rejected launch/preparation charges none; transient infrastructure re-entry retains the same charge/deadline under failures.md.

When actionable findings or red applicable checks remain and `final_fix < retry.final_review`:

1. Save remaining findings/check failures, next round's intent/counter and bounded attempt/deadline. Confirm reviewer/check inactivity, resource safety, route and capacity. Give **one escalate agent** the owned integration worktree as the sole writer for the correction round; use the selected escalate model/effort. Its packet includes exact starting SHA, fixed saved base, frozen inputs, findings/check evidence, agreed commands and original integrated ticket Files/source boundaries. Fix only the authorized integrated scope; report scope expansion/environment errors through failures.md. Preserve blocked work and required behavior/assertions.
2. Capture full correction result, model/lifecycle facts, actual charge and clean committed new integration SHA. Confirm inactivity/release before any checker/reviewer starts. STUCK, unresolved environment/route failure, unsafe state or an exhausted attempt goes to a failed brief under failures.md; no hidden extra correction.
3. Old check/PASS evidence becomes historical on **any** tip/content change. Rerun full suite and applicable typecheck, then **both Standards and Spec** on the new exact SHA using the qualification steps above, even when the fix made checks green. Save all new evidence and remaining findings before deciding another round or delivery. A no-change correction still consumes its started round and reruns checks/both axes.

At the configured limit, remaining findings or red checks require **failed** and a brief listing them. A limit of zero permits the initial check/review only. There is no third correction under defaults. Failed evidence, exhausted budgets, unavailable review/checks or unsafe resources cannot be bypassed by an earlier PASS.

## Tip changes, resume and delivery

Before result/brief or push, recheck current clean tip against **both axes and all checks**. Preserve old entries as historical if tip/content changed; partial or success cannot use them. Explicit resume reconciles through [resume.md](resume.md) first and retains spent rounds/deadlines. For an attributable committed advance with inactive writers, save the invalidation and run one bounded check/two-axis requalification cycle at that exact tip against the same saved base; correction, if needed, uses only the remaining budget. Unexplained movement, dirty/unknown content or another move during qualification stops preserved with failed rather than starting an endless re-review loop.

Done when current-tip checks and both-axis PASS are qualified and the unchanged-tip gate holds, or the finite failed stop is recorded. The brief records final delivered SHA, each axis/base/evidence, check SHA/status/evidence, actual correction count/limit and remaining findings separately from blocked undelivered scope. Result/delivery eligibility remains failures.md's authority.
