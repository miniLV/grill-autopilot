# Resolve one companion set

Read during step 0 before Go, and again when resuming a run. Select a complete source collection, not six files assembled from different installations. These checks establish the contracts needed by this run; they do not certify every upstream release.

## Discover and qualify

1. Discover collection roots in priority order: **adjacent skills** (this skill's parent), then **project skills/plugins** (for example `.agents/skills`, `.claude/skills`, `.codex/skills` and registered project plugin `skills/` roots), then **user skills/plugins** (the host's configured skill roots and installed plugin `skills/` roots, including caches). A candidate root contains the companion directories directly. Enumerate all candidates in a tier before selecting; cache enumeration order, timestamps and version-like names do not decide priority.
2. Canonicalize roots and file targets, and collapse aliases of the same source root. A symlink installation may identify a complete source collection; six independently linked files with unrelated provenance do not establish one. Qualify each candidate independently. Record rejected candidates and the missing/incompatible contract instead of filling gaps from another root.
3. Require readable `grilling/SKILL.md`, `to-spec/SKILL.md`, `to-tickets/SKILL.md`, `tdd/SKILL.md`, `code-review/SKILL.md` and `setup-matt-pocock-skills/SKILL.md` in that collection. Read their bodies and follow necessary packaged relative references for the active workflow, resolving each reference against its containing file. Required packaged targets must belong to this collection; a link into an unrelated installation rejects the candidate. Require the selected setup skill's local tracker helper (`issue-tracker-local.md` in the inspected layout) and any helpers it needs. For the inspected TDD layout this includes `tests.md` and `mocking.md`; the local tracker points to `triage-labels.md`. These examples are a starting inventory, not a permanent filename-only compatibility check.
4. Check the active branches and template semantics in the table below. A missing necessary reference, an unreadable file, or an override that cannot be mapped unambiguously rejects that candidate before Go. Optional inactive tracker templates need not be loaded; project files such as a glossary or standards file are project inputs, not packaged companion dependencies. If an active branch needs another companion beyond the six, check its required source within this same collection before using that branch. Report an unavailable branch instead of importing a different installation silently.
5. Select from the highest tier containing a complete contract-eligible set. If no tier has one, report each candidate's missing files/contract and stop preparation before Go. If multiple eligible sets at that tier have different source/content fingerprints, show canonical roots, source facts and differences and require the user's selection before Go; do not guess the latest. Aliases are one candidate; copies with identical content and source fingerprints are equivalent, so choose one canonical root and record the equivalent copies. Record the selected root and every canonical companion/helper path.

## Semantic contracts and overrides

Read the selected skill's current steps and templates; match an override to what a step does, rather than its number or heading spelling. Stop before Go if the required meaning is absent or ambiguous. Preserve the rest of the selected skill's instructions.

| Companion | Required meaning and autopilot override |
| --- | --- |
| `grilling` | Dependency-aware decision rounds ending in shared understanding; autopilot adds seams, slicing, commands and delivery before its Go checkpoint. |
| `to-spec` | Synthesize the agreed conversation into Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope and Further Notes. Locate the test-seam confirmation by purpose; use the grill's agreed seams. Publish locally through the planner rather than applying an external triage label. |
| `to-tickets` | Draft verifiable vertical slices with blocking edges and publish one local issue per ticket. Locate the human granularity/blocking-edge approval by purpose; replace it with [tickets.md self-check](tickets.md#self-check). The worker-grade template and explicit Files/Context paths replace the selected local template/path restriction. |
| `tdd` | Agreed public seams, external behavior and red before green. Replace its seam confirmation with the seam already agreed in grill; retain its testing rules and necessary references. |
| `code-review` | Review a supplied fixed point and spec on separate Standards and Spec axes. Pass the selected canonical inputs and reviewer role through the existing review protocol. |
| `setup-matt-pocock-skills` | Read the selected collection's local-tracker conventions and their necessary helpers. This is dependency inspection, not permission to run setup, rewrite project/global configuration or copy upstream resources. |

## Fingerprint and resume

For each eligible candidate, capture its source commit when Git/source metadata exists, or explicitly record why it is unavailable. **Also hash the actual bytes of all six skill bodies and the necessary packaged reference closure**, including mutable/untracked helper files even when a commit is known. Record relative name, canonical target and SHA-256 in a stable sorted manifest; source commit alone cannot describe local edits. Missing/read failures are qualification errors, not unknown hashes. Compare source facts and relative-name/content hashes for equivalent copies; retain canonical target mappings separately for resume checks.

Once the run ID is assigned, save the selected tier/root, canonical path mapping, source commit fact, content-hash manifest and semantic-contract evidence under the run record's `companion` fields, using [run-record.md](run-record.md)'s ownership rules before Go. Packets use only this selection; discovering a missing dependency later does not authorize another root.

On explicit resume, recompute source facts, canonical targets and the content manifest against the saved selection before using any companion. An unavailable selected file, changed target/source/content hash, or an uncheckable fingerprint stops resume. Report the exact drift and preserve the run record, input snapshots and worktrees. Keep the old selection/evidence intact; replacing its fingerprint or resetting the installation would conceal the change. Further process/Git recovery decisions belong to the recovery protocol.
