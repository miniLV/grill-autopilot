# SHA-bound review and integration

Read before a worker merges integration tip, before filling a reviewer packet, and for every ticket PASS, merge conflict or failed integration check. This is the transaction authority for [loop.md](loop.md); [run-record.md](run-record.md) owns its fields, [runtimes.md](runtimes.md) owns activity and bounded command waits, and [failures.md](failures.md) owns budgets/terminal exits. Explicit recovery still starts in [resume.md](resume.md). The planner executes this protocol with existing Git/host tools, without a second scheduler.

Ticket candidate review and ordinary merge verification here do not qualify the final delivered tip. After the loop, [final-review.md](final-review.md) requires exact-tip suite/typecheck and both Standards/Spec reviews, including after final corrections.

Command examples are templates: pass refs and canonical paths as literal argv values through the host, or use correct shell escaping for each value. Git-valid names can contain shell syntax; raw substitution inside quote characters is insufficient. Resolve and merge immutable commit SHAs as below.

## Worker tip merge

After committing ticket edits, confirm the owned worktree is clean and no other writer can affect it. Resolve the current integration tip as a commit; capture that fixed SHA, worker pre-merge HEAD, status (including ignored/untracked inventory) and merge intent in the host-captured evidence. Merge that **SHA** into the ticket branch. On conflict, capture command output, HEAD/MERGE_HEAD, status, unmerged index and binary diffs before any restoration. With confirmed ownership, no other writer and no changes beyond this merge, `git merge --abort` may restore the recorded pre-merge state; verify exact HEAD/content afterward. If those facts or abort/restoration are uncertain, retain everything for reconciliation. Report STUCK with the diagnostic pointer either way; a safe abort does not authorize blind continuation. On success, rerun applicable Verify/typecheck and return the clean, unchanged **post-merge** commit as candidate. An earlier review cannot cover this new candidate.

## Qualify and serialize

1. Save the worker candidate SHA and fixed review base SHA (the exact integration tip the worker just merged, from its captured tip-merge evidence), then send the SHA-only diff in loop.md's reviewer packet. This base excludes other tickets already integrated before the worker tip merge; the earlier starting SHA remains preparation history. A valid `PASS <reviewed-sha> <evidence-path>` identifies that candidate and readable evidence for that base, requirements and successful applicable checks. Resolve both objects with `git rev-parse --verify --end-of-options '<sha>^{commit}'`; require the base to be an ancestor of candidate. Capture full verdict/log, reviewer inactivity and model qualification. A bare PASS, missing/mismatching SHA/base/evidence or invalid result follows failures.md; none authorizes merging.
2. Queue qualified PASS results; the planner owns **one active integration transaction**. No next merge, integration check or integration writer starts until the previous merge/check/result/rollback observation is saved and safety established. Other workers may continue in their own worktrees. Before this queued result is consumed, recheck ticket branch tip and worktree HEAD equal candidate, reviewed SHA equals candidate, clean checked content and no active/unknown writer. Recheck input hashes too. Branch advance, staged/unstaged/unknown file changes or candidate change invalidates the queued PASS; preserve evidence and require a newly qualified candidate/review. A later integration tip alone does not invalidate an unchanged candidate's fixed-base review.
3. With owned integration ref/worktree, no pending Git operation and no possible other writer, capture its exact HEAD as `merge_before_sha`, branch tip, clean tracked status and full untracked/ignored inventory. Require an attributable clean integration baseline; unknown files/dirt stop integration preserved. Save transaction identity, candidate/base/review evidence, merge intent and **exact declared generated artifact paths** before running commands. Existing files at those paths are not owned merely by listing them; require absent paths or recorded attributable baseline content. Exclude only recorded, unchanged owned preparation artifacts when qualifying baseline cleanliness. This saved commit is the rollback target; `ORIG_HEAD` is never the target.
4. Immediately recheck the saved refs/HEAD/state, then run `git merge --no-ff <candidate-sha>` in integration and capture its exit/output/HEAD. Record `merge_after_sha` and prove candidate inclusion with `git merge-base --is-ancestor <candidate-sha> <merge-after-sha>`. An ordinary Git merge commit is checked by the integration Verify; unchanged candidate needs no redundant per-ticket review. Unexplained HEAD/ref/content movement stops preserved for reconciliation.
5. Before checks, declare their exact generated paths/expected effects, commands, canonical cwd, bounded attempt/deadline and log destinations. Run all applicable ticket Verify/typecheck at `merge_after_sha`; retain agreed N/A reasons. Capture HEAD/branch/status/diffs/inventory before/after each check and exits/output/times. SHA and checked content must remain unchanged. An expected output does not excuse changing source, index, an existing user file or an undeclared file. After evidence capture, clean only proven transaction-owned artifacts under the gate below. Only passing checks with unchanged clean checked content, unchanged candidate/ref and attributable integration HEAD authorize recording successful checks and then `done`. Save that result **before** releasing the transaction to the next queued PASS.

## Conflict or red check

Capture diagnostics first: transaction SHAs, merge/check output/exits, HEAD/ref/MERGE_HEAD where present, status, unmerged index, staged/unstaged binary diffs and full file inventory with contents/hashes. Keep evidence outside the rollback/cleanup target in declared run-data paths.

- **Conflict:** with the step 3 clean baseline, still-confirmed ownership/inactivity and only attributable merge changes, save abort intent and run `git merge --abort`. Verify HEAD/ref and file state match `merge_before_sha` and baseline; capture the result. Unknown additions/edits, missing facts or abort failure instead preserve the conflict for reconciliation. A safe abort is a business FAIL, never done.
- **Red Verify:** save the failed `merge_after_sha` and check evidence. Before rollback, require HEAD/ref still at that attributable merge commit, no pending operation/writer, and no tracked changes or unknown/changed untracked/ignored files after owned-artifact cleanup. Save rollback intent, then `git reset --hard <recorded-merge-before-sha>` only when these facts establish that it will discard solely this transaction's committed merge. Immediately prove exact restored SHA/ref/content/inventory and record the rollback outcome; earlier integrated tickets remain at that commit. Keep the candidate, merge object and diagnostics. Follow failures.md for the business FAIL, never done.
- **Unknown work or movement:** preserve tracked edits, all unknown files, refs and evidence; stop integration and close failed through failures.md. Do not reset or abort to manufacture cleanliness. Even if a known generated artifact can be safely cleaned, an unknown user file prevents rollback. A failed/uncertain rollback keeps the transaction unresolved and blocks the next queued PASS.

### Owned artifact cleanup gate

Before a check, record each exact canonical output path, its absent/owned baseline, producer command and expected content/type. Afterward capture its actual hash/type and command evidence. Remove/restore only an attributable artifact with no outside writer, no path/symlink redirection and no unexpected content/type; use targeted file operations or restoration of that artifact's recorded owned baseline. Recheck the entire worktree afterward, including ignored files. Path-prefix ownership, whole-directory deletion, blanket `git clean` and cleanup of unrecorded files are insufficient. Any ambiguous artifact is preserved and triggers the unknown-work exit. Cleanup here qualifies a transaction; ticket worktree deletion remains loop.md's separate cleanup gate.
